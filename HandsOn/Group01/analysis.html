Análisis de datos y nombres de recursos

1. Análisis de los datos

Hemos analizado cuatro archivos CSV obtenidos de los portales de datos abiertos de Madrid.

Los archivos CSV utilizados son los siguientes:

  • Fuentes de agua potable: Enlace al CSV
  • Aseos públicos: Enlace al CSV
  • Bibliotecas públicas: Enlace al CSV
  • Polideportivos: Enlace al CSV

Los archivos comparten datos similares que podemos relacionar entre sí:

  • Un identificador único o número de registro para cada elemento.
  • El nombre o la descripción del servicio.
  • La dirección donde se encuentra (calle, número, barrio, etc).
  • Las coordenadas geográficas (latitud y longitud) para situarlos en un mapa.

2. Licencia de los datos

3. Estrategia para nombrar los recursos (URIs)

Para identificar de forma única cada elemento de nuestra aplicación web, utilizaremos direcciones web (URIs) siguiendo una estructura clara y organizada.

Dirección base de la aplicación: http://madridservices.linkeddata.es/

3.1. Clases de la ontología

Las clases se identificarán utilizando la siguiente ruta:

  • Servicio (Clase padre): http://madridservices.linkeddata.es/ontology/services#Service
  • Fuentes: http://madridservices.linkeddata.es/ontology/services#DrinkingFountain
  • Aseos: http://madridservices.linkeddata.es/ontology/services#PublicToilet
  • Bibliotecas: http://madridservices.linkeddata.es/ontology/services#Library
  • Polideportivos: http://madridservices.linkeddata.es/ontology/services#SportsCenter

3.2. Propiedades de la ontología

Las propiedades utilizarán una ruta independiente de la utilizada para las clases:

  • Ubicación (enlace a ciudad): http://madridservices.linkeddata.es/ontology/properties#locatedIn
  • Nombre: http://madridservices.linkeddata.es/ontology/properties#name
  • Dirección: http://madridservices.linkeddata.es/ontology/properties#address
  • Latitud: http://madridservices.linkeddata.es/ontology/properties#latitude
  • Longitud: http://madridservices.linkeddata.es/ontology/properties#longitude

3.3. Individuos de la ontología

Para identificar cada lugar o servicio concreto utilizaremos su número de ID. Cada tipo de individuo tendrá una ruta diferente según su clase:

  • Ejemplo de una fuente: http://madridservices.linkeddata.es/resource/DrinkingFountain/10040803
  • Ejemplo de un aseo: http://madridservices.linkeddata.es/resource/PublicToilet/020035ASW
  • Ejemplo de una biblioteca: http://madridservices.linkeddata.es/resource/Library/1774
  • Ejemplo de un polideportivo: http://madridservices.linkeddata.es/resource/SportsCenter/4696

De esta manera, las clases, las propiedades y los individuos tendrán rutas diferenciadas. Además, los individuos de distintas clases utilizarán rutas específicas para evitar confusiones y garantizar su identificación única.
